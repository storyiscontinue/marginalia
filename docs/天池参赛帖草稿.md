## 二、你的作品是什么

一句话：**研究生读一篇陌生的英文论文时，用它逐段读懂，把每个卡住的地方连同自己的理解批注在原文页边，下次再遇到这个词，它记得你当时的困惑。**

它交付三件事：

- **扔进来就能读**：拖入你自己的 PDF，段落重建在你浏览器里当场完成（双栏、脚注、图注、目录页都有规则），不需要论文有 arXiv 网页版。
- **困惑留在页边**：划任意一句 →「解释这句 / 这是术语 / 提问… / 只写批注」。问题和 AI 的答案一起写进那一句的批注卡；你可以改写它，改写后以你的版本为准；删掉只删这一句，术语本上的词仍然留着——批注是逐句的，词汇是累积的。
- **不装万能**：PDF 文字层里没有的东西就明说没有。公式在 PDF 里只剩打乱顺序的字母，所以我们不生成"看起来对"的公式卡；页首一段说明写清哪些没读入、为什么没读入、丢了几个数字都报数。

（**创新点就一条**：市面工具的共同逻辑是"帮你跳过读"，我们做的是"陪你读进去、并且把你的困惑变成可复用的资产"。翻译和划词解释是基础设施，不是卖点。）

## 三、为什么做

我一开始以为痛苦来自"英文不好、读得慢"。用了翻译插件之后发现不是——整篇都"译成了中文"，我还是不知道自己读懂了没有。我把卡壳的地方归成四类，前三类现有工具都不解决：

1. **卡壳点在结构不在句子**：公式 (3) 到 (5) 之间发生了什么、图 2 到底想说明什么。整篇翻译一遍照样不懂。
2. **前置知识断层**：第 2 页一个术语直接拦死，而且我不知道自己缺的是什么。
3. **没有反馈**：读了三小时，不懂"自己懂了多少"，是一种幻觉式理解。
4. **读完讲不出来**：组会上被导师一问就崩。

而"打开就能用"这件事，是被我自己的账号条件逼出来的：我没有第三方 API Key，也不该让同学为了读一篇论文先去申请一个。所以这个产品从第一行代码起就被三条硬约束框死：**零登录、零配置、零 Key**。回头看，这三条约束比任何功能都更能定义它。

【建议在这里补 1–2 句你自己的真实经历，比如哪篇论文、卡在哪一节。这一段是全帖最不可代写的部分，也是评委判断"真想解决一个问题"的地方。】

## 四、怎么用（评委照这 5 步就能跑完）

1. 打开 **https://marginalia-reader-ni20c3jx4cs.qoder.zone** —— 首屏直接是一篇预置论文（Attention Is All You Need）的双语对照正文，不需要任何输入。
2. 点右上角 **「换一篇」**，把你自己的英文论文 PDF 拖进去（也可以只粘贴一个 arXiv 编号）。几秒之内，正文按版面重建出来，作者行、章节、页码都在。
3. 在任何一段下方点 **「译这段」** —— 只译你点的那一段，译文存本机。
4. 在原文上**划住一句话**，浮出工具条，点 **「解释这句」** —— 通常几秒到十几秒（后端排队时更久），问题和答案一起出现在这一句右侧的页边批注里。
5. 试试它的两件事：**改写**这条批注（保存后以你的版本为准）、**删除**它（这一句的眉批没了，术语本上的词还在）。刷新页面，论文、译文、批注全部从本机恢复。

## 五、用 Qoder 做出来的过程

开发全程在 Qoder 里完成，部署用 Qoder Sites。下面按"我提了什么 → Qoder 做了什么 → 我推翻/改了什么"来写，因为**真正花时间的地方是我否掉它的三次**。

**① 先让它把平台边界测清楚，而不是先写功能。** 我要求它在写第一行业务代码前，把 Qoder Sites 的能力实测一遍：静态目录 + 一个 `app` Deno Edge Function、打包器**不装 npm 依赖**、后端只有一个函数入口。这些数字和限制都是从真实调用里拿的，不是猜的。

**② 它据此判定"PDF 解析做不了"，我不认，于是架构反转。** 这是全项目最重要的一个来回。它的推理是：`pdfjs-dist` / `PyMuPDF` 这类解析库进不了 Function,所以服务端解析 PDF 结构上不可行——**前半句到今天仍然成立**。我逼它继续想，结论变成了：这条限制真正的含义不是"做不了 PDF"，而是"**只能在浏览器里做**"。pdf.js 本来就是浏览器库，`?worker` 打进前端产物即可，云端一行解析代码都不需要。
这个反转顺手把产品变好了：用户的论文**不出本机**，隐私论述从"我们不存"升级成"我们收不到"。
> 📷 截图 3、4 放这段：上面那条"结构上不可行"的判断，和反转后浏览器端解析出来的真实版面。

**③ AI 链路：零 Key 怎么成立。** QCA 的调用凭证只以平台 Secret 的形式存在于 Function 内部（`Deno.env.get`），前端永远碰不到 Key，也就没有任何同学需要自带 Key。代价是每次解释要轮询、要排队，所以做了**每请求独立 Session + 有界轮询 + 上游 429 一次有界重试**；并把"单次可提交文本长度"做成 400 拒绝而不是悄悄截断——**截断会让读者以为自己得到了完整答案**。

**④ 版面重建：一条真实论文配一条断言。** PDF 侧最难的不是读字，是把"阅读顺序"重建出来。最后形成四条规则，每条阈值旁边都写着它是被哪篇论文的哪个版面逼出来的：按字号断段、按图注标记断段（`Figure 3.16:` 这种）、碎片（坐标轴刻度 / 单元格数字）丢掉并计数、被整页插图切断的半句往回找它的段落。
回归基线是**七篇真实论文的常驻夹具、164 项断言**：Attention、ResNet（双栏 CVPR）、GPT-3（75 页），加上四篇非 CS 模板（数学、经济、LNCS 会议版、IEEE 地球科学）。后四篇逼出了最典型的三个坑：24.9 pt 的封面行距让"页面底部留空即脚注"误杀，拼成 "Institue" 的机构名让作者识别把一行地址当成第三作者，`http://isp.uv.es/` 因为冒号两侧都没有词字符而进了作者名。
> 📷 截图 8：那张 164 项断言全绿的终端输出。这是评委最能直接核验的一张。

**⑤ 我推翻的另外两件事。**
- **入口**：Qoder 一度把方案收窄成"只做 arXiv 覆盖的领域 + 粘贴链接"。我否掉了——研究生手里的是 PDF，不是链接。于是 PDF 上传成为主入口，链接降为辅助路线（它仍值得留着，因为能拿到 PDF 里没有的章节层级和公式原始 LaTeX）。
- **翻译**：方案原本是"导入即全篇译好、双语常驻"。改成**每段按需「译这段」**，理由是每次 AI 调用都要走一个一次性 Session（约 8 次上游请求），打开就全译等于在读者还没决定要不要看译文之前，先替他烧掉几十次这样的开销；而且"读者点了哪几段"本身就是他没读懂哪些段落的信号。

**⑥ 诚实降级是它主动提的，我把这条留住了。** 扫描件没有文字层，返回的是"这里不做 OCR：与其给你一份满是错字的正文，不如直说读不到"，并把用户引回 arXiv 路线；页首如实报告"图和表里的 N 行文字没有读入""页面底部的 N 行脚注没有读入""扉页的 N 段标签没有读入""解析时遇到 N 处跨行断词，连字符原样保留"。**删掉了多少，就报告多少**——这是我给它定的一条验收线。

**⑦ 还有一次我让它返工，是因为安全问题。** 开发中途它提议临时开一条公网路由来完成后端初始化，我拒绝了，并且要求这条路由在后续每个版本里都必须保持 404；线上验证脚本里现在有一条断言专门盯它。任意 URL 不能变成带凭证的代理目标，这是我自己都不该越的线。
