## 0. 命名提案

**Marginalia / 眉批**

Marginalia 指学者在书页空白处写下的批注，是西方学术传统里最古老的阅读方式；「眉批」是对应的中文传统术语。这个名字直接命名了本产品的灵魂——**你的困惑与理解，沉淀在原文的页边**。

它同时满足三个评审场景的需求：好记、有学术气质、能在 50 个"文献 AI 助手"里被一眼区分。绝大多数学生作品会叫"XX 文献助手""Smart Paper Reader"，名字本身就是印象分。

*（命名可在动手前替换，但建议尽早锁定，因为视觉标识和帖子标题都依赖它。）*

## 1. 一句话定位

> **你读英文文献时问过的每一个问题，都会变成你自己的页边批注库——下次再遇到，它记得你当时的困惑。**

注意这句话里**没有"翻译"、没有"总结"、没有"划词解释"**。这三个都是商品能力，放进定位句会让评委的第一印象掉进最拥挤的一档。它们是基础设施，不是卖点。

**一句话说清谁在什么场景下用**（帖子必填项）：
研究生在读一篇陌生的英文论文时，用 Marginalia 逐段读懂它，把每个卡住的地方连同自己的理解批注在原文页边，最后生成一份能在组会上直接念的汇报稿。

## 2. 核心判断与取舍

这一节记录"为什么这么做"，帖子和路演都要用到。**取舍讲清楚比功能堆得多更加分。**

### 2.1 痛点重新定义

研究生读英文文献的痛苦**不是看不懂英文**。翻译工具早就解决了这一层。真实痛点是四条：

| # | 痛点 | 现有工具是否解决 |
|---|---|---|
| 1 | 卡壳点在结构不在句子：公式(3)到(5)之间发生了什么、图2想说明什么 | ✗ 翻译整篇也不懂 |
| 2 | 前置知识断层：第2页一个术语直接拦死，不知道自己缺什么 | ✗ |
| 3 | 没有反馈：读3小时不知道自己懂了多少，是"幻觉式理解" | ✗ |
| 4 | 读完讲不出来：组会被导师一问就崩 | ✗ |

竞品（ChatPDF / SciSpace / Readpaper / Kimi）的共同逻辑是"**帮你跳过读**"。本产品的逻辑是"**陪你读进去，并让你能讲出来**"。

### 2.2 关键取舍一：入口是"把你的 PDF 丢进来"，arXiv 链接降为辅助（11/16 修正）

**现在的决定**：主入口是拖入 / 选择用户自己的 PDF，解析**全部在访客浏览器里完成**；arXiv 编号导入保留为第二条路，因为它能拿到 PDF 里没有的东西（章节层级、每个公式的原始 LaTeX）；另有一篇预置示范论文保证"零操作出啊哈"。覆盖范围因此重新变成**全学科**——只要它有文字层。

**这条被推翻的判断是什么**：原文写"PDF 解析在这个平台上不是难，是结构上不可行"，理由是 Qoder Sites 的后端是单个 Deno Edge Function，打包器不装依赖，`pdfjs-dist` / `PyMuPDF` 都进不去。**前半句到今天仍然成立**：Function 侧确实解析不了 PDF。错的是把它当成"所以做不了 PDF"——它真正的含义是"**所以只能在浏览器里做**"。pdf.js 本来就是浏览器库，`?worker` 打进前端产物即可，云端一行解析代码都不需要。

这个反转还顺带把方案变好了：用户的论文**不出本机**，服务器上不留副本，隐私论述从"我们不存"升级为"我们收不到"。

**代价，实测记在案**：

1. 前端体积。pdf.js 主块 445 kB（gzip 134 kB）+ worker 1.18 MB，按路由懒加载，只有真正导入 PDF 的访客才下载。
2. 版面重建是新的主战场。双栏、脚注、图注、目录页、扫描版没有文字层——这些原先判定"会吃掉两周且产出不稳"的风险并没有消失，只是从"不可行"变成了"可迭代"。现在的做法是**几何 + 字号规则 + 一条真实论文一个断言**：`lib/pdf-layout.ts` 的每处阈值旁边写着它是被哪篇论文的哪个版面测出来的。
3. 拿不到的东西就明说。公式在 PDF 文字层里只剩打乱顺序的字母，所以导入的论文**不生成公式卡**，页首一条说明写清"下面这些没有，因为 PDF 的文字层里本来就没有它们"，而不是拼一条错公式糊上去。

**保留下来的产品判断**：主打楔子仍是"公式人话拆解"，只是它现在长在预置示范论文和 arXiv 导入这两条路上；PDF 路线交付的是"逐段陪读 + 划词解释 + 按需翻译"。这两句话在帖子里要分开说，不能写成"什么都能拆公式"。

**帖子里的说法**：讲清这个反转——先认定平台不能解析 PDF，于是走链接抓取；后来发现限制只是"不能在服务端做"，就把解析搬进浏览器，顺手解决了隐私。**这是 Qoder 协作下真实发生的架构决策，比一开始就想对更能说明问题。**

### 2.3 关键取舍二：翻译降为背景能力

浏览器自带翻译、沉浸式翻译免费、DeepL 免费、知云文献翻译做了十年。把翻译当第一卖点，作品第一印象就变成"一个翻译工具"。

**处理方式**：默认双语对照常驻，但不写进定位句、不做首屏标题、不在帖子里当创新点讲。

**实现修正（11/7）**：「常驻」只对预置示范论文成立——它的中文是人工写好、随数据一起加载的。**导入的论文改成逐段按需翻译**：每段下方一个「译这段」按钮，点了才生成，生成后存本机。

理由是 R12 那条账：一篇 60 段的论文如果打开就全译，等于在读者还没决定要不要看译文之前，就先替他烧掉 60 个一次性 Session（每个约 8 次上游调用）。**Session 堆积不是免费的，而"默认全译"是把这笔开销无条件前置。** 按需翻译还带来一个产品上的好处：读者点了哪几段，本身就是"这几段他没读懂"的信号，将来做宏观层时这是现成的输入。

代价也如实记：想通读全文译文的读者要点 60 次。这是有意识的取舍，不是没做完。

**上线确认（11/16）**：这条已在公网跑通。导入的 ResNet PDF 第 7 段点「译这段」→ 6.6 s 返回 → 中文渲染在该段下方 → 写入 `marginalia:translations:<文档号>` → 强刷后仍在。译文按文档分键存放，换论文不会串台。

### 2.4 关键取舍三：v1 砍掉"用户自带 API Key"

**规则层面（硬性）**：赛题作品要求明文写着"**怎么用（5 步以内，评委照着能自己打开用起来）**"；常见问题里写"**必须用 Qoder 部署到公网、别人点开就能用**"。让评委填 API Key，结果就是他看到空壳然后关掉。初赛 1045 队筛 42 队（通过率 4%），评委每份作品约 2–3 分钟，**这个错误没有第二次机会**。

**工期层面**：Key 存 localStorage 有安全观感问题；多 provider 适配（OpenAI / Anthropic / DeepSeek / 通义格式各异）、错误处理、余额提示……全是工作量，路演一秒都演示不到。

**取舍说明**：自带 Key 对"真产品"是优点（成本可控、隐私自主），对"25 天参赛作品"是致命伤。写进 v2 roadmap。

**替代方案**：默认走服务端 Secret（`Deno.env.get('APP_API_KEY')`）+ 限流的内置额度，评委零配置点开就用。

### 2.5 关键取舍四：纯被动划词有天花板，必须加宏观层

**这是最重要的一条产品洞察。**

用户划词的前提是"**他知道自己不懂**"。但研究生读文献最深的痛苦恰恰是**读完以为自己懂了，组会上被一问才发现根本没懂**——学习科学里这叫 unknown unknowns，或"幻觉式理解"。

一个纯被动等待划词的工具，服务的是"已经知道自己不懂"的人，而真正的痛点在另一部分人身上。**这决定了纯划词模式的价值上限。**

因此采用**微观 + 宏观双层架构**（见 §3），两层咬合而非二选一。

## 3. 产品形态：微观 + 宏观双层

| 层 | 谁触发 | 解决什么 | 数据归属 |
|---|---|---|---|
| **微观沉淀层** | 用户主动 | "我不懂这句" | 属于用户，可编辑，会复利 |
| **宏观导航层** | 系统主动 | "我不知道我该懂什么" | 系统生成，共性 |

### 3.1 微观沉淀层（产品的灵魂）

交互链路：

1. 原文默认双语对照（中文可折叠）
2. 用户在原文上**划选任意句子/片段**
3. 浮出工具条：`解释这段` / `术语` / `公式` / `自定义提问` / `仅做批注`
4. AI 解释后，**问题与答案一起写回该句子的页边批注**
5. 批注**可由用户自行删改**——最终所有权归用户

第 4、5 步是真正的创新点，其余都是输入方式。

**为什么这两步是护城河**：市面所有 AI 读论文工具都是**内容服务**（你问，它答，答完蒸发）。Marginalia 是**学习记录**——困惑被锚定在原文的具体位置，变成持久、可编辑、属于用户的资产。它会**复利**：用得越久越值钱，且换不掉，因为内容是你自己长出来的。总结型产品没有这个属性，用户今天用你明天用别人毫无成本。

第 5 步还有哲学立场：**工具承认"AI 的解释"不等于"你的理解"**。这一点在路演时讲出来是有分量的。

**微观层的两个放大器（护城河的实际来源）：**

- **跨论文术语记忆**：你在 A 论文问过 "ablation study"，三周后读 B 论文再遇到，工具浮出提示"你 3 周前问过这个，当时你的理解是 XX"。**这是只有沉淀型产品做得到的事，总结型产品在结构上就做不了**，且依赖用户自己的历史数据，无法被抄袭。路演演示这个，杀伤力最大。
- **批注密度热力图**：哪一段被划的批注最多，说明那是全文最难或最核心的地方，可提示"这一段是卡壳高发区"。有网络效应的想象空间，是很好的"未来性"论证。

### 3.2 宏观导航层

- **段落功能标注**：每个阅读单元标注它在全文中承担什么角色（提出缺口 / 承认前人不足 / 引入记号 / 核心假设 / 方法步骤 / 实验设置 / 结果 / 兜底说明）。让用户看见论文的**论证骨架**而非句子堆叠。
- **公式人话拆解**：每个编号公式给「符号表 + 逐项怎么读 + 它被正文哪里引用」。
- **图表意图解读**：回答的不是"图里有什么"，而是"**作者想让你从这张图得出什么结论**"。
- **前置知识缺口探测**：进入论文前，先给"读这篇你需要知道的 5 个概念"，每个 3 句话解释。
- **理解检查 + 组会产出物**：见下。

### 3.3 两层的咬合点

宏观层生成的理解检查题，**如果你答错了，那道题和正确答案也沉淀成一条批注**。闭环。

### 3.4 组会产出物（重要修正）

**不做成对话。** 对话式功能在被评审的场景里天然吃亏——它是个聊天框，而聊天框是最不稀缺的东西，评委见过一百个；且效果依赖用户输入质量，评委随手打两个字得到的回应就平庸，反而拉低印象。

**做成两个可下载的产出物**：

1. **3 分钟组会口播稿**
2. **导师最可能问的 5 个问题 + 你的应答要点**

**在评审场景里，一个具体的产物永远比一段对话更有说服力。** 而且这两张截图放进帖子，比任何文字描述都能证明"这东西真的有用"。

## 4. 首屏与演示主线

### 4.1 最高优先级的单一决策：首屏即产品，零操作出"啊哈"

初赛 1045 → 42（4%），初筛是评委看**论坛帖 + 一个链接**。现实估计：**每份作品 2–3 分钟，且评委大概率不会深度使用你的应用**。他们读帖子、点开链接、看首屏、最多随手点一两下。

因此：

- **落地页不是介绍页、不是 demo 页、不是"上传/输入"空状态**
- **落地页就是一篇真实论文正在被陪读的样子**：左边原文，右边一段功能标注，底下一个公式正在被逐项拆解
- 预加载一篇**评委全都认识**的论文（`Attention Is All You Need`，arXiv:1706.03762，全场无人不晓），打开直接落在它的核心公式那一段
- **零操作、零登录、零等待**，10 秒内拿到"啊哈"

如果首屏是空状态，评委看到的就是一个空白输入框，10 秒内关掉。

### 4.2 路演 3–5 分钟主线

1. 打开即是 Attention 论文的核心公式拆解（0 操作，10 秒出效果）
2. 划一句看不懂的话 → AI 解释 → **问题与答案落进页边批注**
3. 换一篇论文 → 遇到同一术语 → **浮出"你 3 周前问过这个"** ← 全场最高点
4. 点"组会准备" → 生成口播稿 + 5 个导师可能问的问题
5. 一句话收尾定位

## 5. 功能清单与优先级

**P0（死保，缺一不可）**

- 首屏预置论文，零操作可见完整陪读效果
- arXiv 链接/ID 输入 → 结构化 → 逐段双语对照
- 划词 → AI 解释 → **问题+答案写回页边批注** → 可删改
- 段落功能标注
- 公式人话拆解（符号表 + 逐项读法 + 引用位置）

**P1（次保，时间够就做）**

- 理解检查题 + 答错沉淀为批注
- 组会产出物（口播稿 + 5 问）
- 跨论文术语记忆（护城河，尽量保）
- 阅读脊柱进度条（视觉标识 + 功能）
- 批注导出 Markdown

**P2（有余力）**

- 前置知识缺口探测
- 图表意图解读（依赖 VLM，成本与稳定性风险高）
- 批注密度热力图

**直接砍掉，不要犹豫**

多篇成网 / 综述图谱 / 账号体系 / 移动端深度适配 / 自带 API Key / PDF 上传 / Anki 导出 / 深色模式

第 4 类里的东西做了不会加分多少，但会吃掉最后 5 天的缓冲。

## 6. 技术架构（基于已核实的平台约束）

### 6.1 已核实的约束（不是猜测）

| 约束 | 内容 | 架构影响 |
|---|---|---|
| Function 形态 | 单个 `app` Edge Function，runtime = `edge`（Deno），入口 ZIP 根目录 `index.ts`，`Deno.serve(...)` | 无持久后台进程 → **长任务不能异步跑** |
| 依赖 | 打包器**不安装依赖、不解析 TS 路径别名、不转换 Node 模块**；依赖需随目录自带且自包含 | **PDF 解析库全部不可用** → 只能走 arXiv |
| 路由 | 支持逻辑子路径 `/functions/v1/app/xxx`；不能假设函数收到的完整 pathname 含 `app` | 需显式适配真实 request path，未知路径不能都返回成功 |
| Secret | `Deno.env.get('APP_API_KEY')`，在 `prepare_site.secretNames` 声明；缺失时返回稳定错误 `service_not_configured`；**禁止打印环境变量或返回其值/摘要** | LLM Key 放服务端；前端不暴露 |
| 外部调用 | 应使用**固定的可信服务端目标**、超时、过滤响应；**不得把任意用户 URL 变成携带凭证的代理目标** | arXiv ID 必须严格正则校验，URL 由服务端用固定 base 拼接，防 SSRF |
| 数据库 | `prepare_site.databaseAccess` = `none`/`read_only`/`read_write` + `schemaRef` | 见 §6.3 降级方案 |
| Storage | 部署时注入 `./_qoder/storage.mjs`；**不得打包 `_qoder` 目录**；需在 `dev/` 放无凭证 fake | v1 不需要（不做 PDF 上传） |
| 访客身份 | Gateway 注入 `x-qoder-user-context`；**公开站点可能有匿名访客**；浏览器传的 user ID 不是可信身份 | 匿名用户数据走 localStorage，见 §6.3 |
| 发布预览 | **publication preview 只渲染前端，不执行 Functions** | 必须用已发布站点验证 AI 链路，排期要留出时间 |
| 配额 | 存在 `sites_total`、`backend_sites`、`storage_bytes`、`artifact_size_exceeded`、`sites_rate_limited`、日 PV 限制 | **`backend_sites = 0` 时只能部署静态站**，见 §12 风险 R1 |

**未核实、需实测**：Edge Function 的单请求执行时长上限（参考文档未给出具体数值）。架构上按"可能只有几十秒"防御性设计：SSE 流式返回 + 分段计算 + 结果缓存。

### 6.2 架构总览

```
浏览器（React + Vite，静态输出）
  ├─ 首屏：预置论文 JSON（打包进静态资源，零请求、零成本、秒开）
  ├─ 阅读器：双栏（左 arXiv HTML 原文 / 右陪读面板）
  ├─ 批注数据：localStorage（匿名可用，零登录）
  └─ 同源调用 /functions/v1/app/*（含 SSE 长连接）
        ↓
Edge Function `app`（Deno，单入口，子路径路由）
  ├─ 零依赖 fetch arXiv HTML → 粗清洗（正则/字符串）
  ├─ 复制 cloud-agents.mjs + sse.mjs 到函数目录，相对导入
  ├─ Authorization: Bearer <QODER_PAT> → Qoder Cloud Agents
  │     origin 取自 get_context 的 runtime.cloudAgents.apiOrigin（已核实 configured:true）
  ├─ /parse?arxiv_id=   分段送 Agent 结构化 → JSON 校验+重试兜底 → 写缓存
  ├─ /explain           划词解释（带上下文窗口，SSE 流式回推）
  ├─ /check             理解检查题生成 + 评分
  └─ /pitch             组会产出物生成
```

**AI 能力来源（已核实，重要）**：使用平台原生的 **Qoder Cloud Agents (QCA) Managed API**。开启 `qoder` 后端时，平台**自动为账号创建 Qoder PAT 并注入服务端** `QODER_PAT`，`ensure_backend` 该步骤"includes Functions and provisions the platform Secret"。

- **不需要购买任何第三方 API Key**，也不需要用户填写任何凭证
- 文档明写 **"Anonymous Function mode alone does not prevent server-side QCA calls"** → 匿名访客（不登录）可触发服务端 AI 调用，**"打开就能用"与"有 AI 能力"同时成立**
- `QODER_PAT` **只在 Function 内**通过 `Deno.env.get('QODER_PAT')` 读取；不得写进 `prepare_site.secretNames`、不得传入浏览器、不得让用户粘贴

**关键的架构决定：用 Agent 做结构化，而不是用解析库。**

因为 Function 里装不了任何解析库，所以"把论文切成阅读单元、标注功能、抽公式"这件事**交给 QCA Agent 完成**。服务端只做零依赖的 `fetch` + 粗清洗，然后送 Agent。结构化结果**一次计算、永久缓存**，同一篇论文的第二个人打开是零成本的。

### 6.2.1 QCA 是异步 Agent，不是同步补全 API

已核实的真实接口契约：

| 操作 | 接口 |
|---|---|
| 发现模型 | `GET /api/v1/cloud/models`，选一个 enabled 的 `id` 并**保持稳定** |
| 定义 Agent | `POST /api/v1/cloud/agents`（`name`/`model`/可选 `system`/`tools`/`metadata`），保留 `Idempotency-Key` |
| 定义 Environment | `POST /api/v1/cloud/environments`（`name`/`config:{type:'cloud'}`）；**新账号必须显式创建** |
| 开对话 | `POST /api/v1/cloud/sessions`（`agent` + `environment_id`，可 pin Agent 版本） |
| 发消息 | `POST /api/v1/cloud/sessions/{id}/events`，最小载荷 `{events:[{type:'user.message',content:[{type:'text',text}]}]}` |
| 读进度 | `GET .../events?order=asc&limit=100`（游标分页，响应含 `data`/`has_more`/`next_page`） |
| 流式 | `GET .../events/stream`，客户端 `openStream(sessionId,{lastEventId,signal})`，请求 `event_deltas[]=agent.message` |

**由此产生的四条设计约束：**

1. **202 只代表"已接受"，不代表"已回答"**。必须轮询或 SSE 取结果。发送时若 Session 正在运行返回 **409 且消息未入队**，需等空闲或显式中断。
2. **无 `response_format: json_schema` 类强约束**。`/parse` 需要的严格 JSON 只能靠 Agent 的 `system` 指令 + **Function 侧 JSON 校验与失败重试兜底**。这是必须写的防御代码，不能省。
3. **不得跨用户共享 Session 或可写 Environment**。匿名公开访问下每个访客需独立 Session；无状态、无用户数据的 Environment 模板**仅在"每个 Session 获得隔离运行时"的契约成立时**才可复用。用户特定的状态必须绑定到其 session。
4. **只发布应用选定的 message/status 内容**，不得转发原始 prompt、工具参数、内部思考、凭证或账号元数据。**绝不接受公开请求传来的任意 URL、PAT、Agent 配置或工具定义。**

**收益**：原生 SSE 流式让风险 R2（长论文超时）大幅下降——可分段计算边算边推，且逐字出现的体验在路演时更好看。

**成本形态变化**：R3 没有消失，只是从"第三方 API 账单"变成"你的 Qoder 账号额度"。缓存 + 限流照做。学生认证赠送的一个月 Qoder CN 免费权益可覆盖开发期。

**Prompt 尺寸**：整篇论文文本可能达数万 token，**不得一次性塞进单条 `user.message`**。按章节分段送入，这也正好契合 SSE 与阅读单元的粒度。

**本地校验**：`deno check --node-modules-dir=none functions/index.ts`（`cloud-agents.mjs` 是 JS 但带参数类型，可供 TS 调用方使用）。

**发布验证**：publication preview **不执行 Functions**，AI 主链路必须用**已发布站点**实测一次真实对话（消息被接受 + 收到最终回复 + SSE 增量可见）。

### 6.3 优雅降级设计（这一条可能救整个参赛）

按依赖强度分三档，**核心体验不依赖后端**：

| 档 | 能力 | 依赖 |
|---|---|---|
| **A 档：纯静态** | 首屏预置论文 + 完整陪读视图 + 划词批注 + 批注存 localStorage + 术语记忆（本地） | **零后端、零配额、零 Key** |
| **B 档：+ Secret** | 用户贴新 arXiv 链接实时解析、AI 解释、组会产出物 | Functions + Secret |
| **C 档：+ Database** | 跨用户缓存解析结果、批注热力图聚合 | Functions + Database |

**为什么这样分**：如果 `backend_sites` 配额为 0（只能部署静态站），产品**不会死**——A 档仍然是一个完整的、可批注的、有预置论文的精读阅读器，只是不能解析新论文。这比"整个作品打不开"好一万倍。

同时，**批注存 localStorage 而非数据库**，一举三得：

1. 评委零登录即可完整体验（规则要求"点开就能用"）
2. 绕开"浏览器传的 user ID 不是可信身份"这个平台约束——本地数据不需要身份
3. 符合平台指引"浏览器存储用于设备本地偏好或显式本地状态"

登录用户可选做云端同步（v2）。

### 6.4 前端

- React + Vite，静态输出
- 左侧原文：arXiv HTML 清洗后渲染（**不用 pdf.js**，Function 装不了、前端也不必）

## 8. API 契约

统一前缀 `/functions/v1/app`。全部 POST（GET 不得改状态），显式校验 method、body 类型与大小。

| 端点 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `/parse` | `{ arxiv_id }` | `{ ok, meta, units, formulas, ... }` | 先查 `papers_cache`，命中直接返回；未命中则抓取+LLM结构化+写缓存。**arxiv_id 严格正则校验**（`\d{4}\.\d{4,5}(v\d+)?` 或旧格式），URL 由服务端固定 base 拼接 |
| `/explain` | `{ arxiv_id, unit_id, selected_text, question?, mode }` | `{ ok, answer, term? }` | mode ∈ `sentence`/`term`/`formula`/`custom`。带该 unit 及前后各 1 unit 作上下文窗口 |
| `/check` | `{ arxiv_id, unit_ids[] }` | `{ ok, questions[{q, hint}] }` | 生成 2–3 道理解检查题 |
| `/pitch` | `{ arxiv_id, annotations[] }` | `{ ok, script, likely_questions[{q, points}] }` | **把用户的批注一起送进去**，产出物因此是个性化的 |

**错误约定**：Secret 缺失 → `service_not_configured`；限流 → `rate_limited` + retry hint；上游失败 → `upstream_error`。**永不返回原始上游异常、环境变量值或摘要。**

**限流**：按 IP + arXiv_id 双维度，`/parse` 每小时上限，`/explain` 每分钟上限。结果缓存是主要的成本控制手段。

## 9. Prompt 设计要点

**结构化 Prompt（/parse）**
输出严格 JSON Schema。`discourse_role` 用**封闭枚举**（不让模型自由发挥），否则前端无法稳定渲染：
`gap | prior_work_limit | notation | hypothesis | method_step | experiment_setup | result | caveat | transition`

**功能标注的质量关键**：要求模型标注"这段在**全文论证链条**中的角色"，而非"这段讲了什么"。前者产生导航价值，后者退化成摘要。

**划词解释 Prompt（/explain）**
- 强制回答三件事：这句话在说什么 / 为什么作者要在这里说它 / 它和上下文的连接
- **术语解释必须给"你之前可能熟悉的类比"**，而非词典定义
- 输出长度上限约束（页边批注不是论文，超过 150 字就没人看）

**组会产出物 Prompt（/pitch）**
- 输入必须包含用户自己的批注 → 产出物才是"你的"而非通用的
- 5 个问题要覆盖：与相关工作的区别 / 消融假设 / 局限性 / 可复现性 / 对你自己课题的启发
- 口播稿按 3 分钟 ≈ 450 中文字严格控制

**理解检查题 Prompt（/check）**
- 禁止出"文中提到了什么"这类检索题，只出**需要推理才能答对**的题
- 每题附 `hint`，答错时才显示

## 10. 视觉方向

**问题**：绝大多数学生作品会是"默认 Tailwind 白底 + 一个聊天框"。只要不是那个样子，就已经赢了一半印象分。

**视觉论点**：**页边批注的纸感**。

- 主色：暖白纸底（非纯白 `#FFFDF8`）+ 墨黑正文 + **一个高饱和的批注色**（朱砂红 `#C8442A` 或靛蓝），批注色只用于用户内容，形成"这是我的"的视觉所有权
- 字体：正文用衬线体（学术论文的阅读质感），UI 用无衬线
- **阅读脊柱**：纵向进度线，章节为节点，当前位置高亮，像登山路线图。它同时是视觉标识和功能元素（进度感、成就感），**在帖子里截一张图就极有辨识度**
- 批注以**真实的页边距悬浮卡片**呈现，带轻微手写体倾斜或纸张阴影，而不是聊天气泡
- 公式拆解区用左侧竖线标记，视觉上像"批注"而非"答案"

一句话：**让它看起来像一本被认真读过的书，而不是一个 AI 产品的后台。**

### 6.5.3 explain 全链路真实验证结果

`explain` 已实现并公开发布，四种模式全部实弹通过，7–9 秒返回：

### 6.5.4 arXiv 真实论文导入：出口问题实测闭环（11/7）

**这一节回答的是整份规划书里最后一个未知数：部署后的 Function 能不能访问公网。** 之前所有 AI 链路都只打 `api.qoder.com.cn`（平台自己的上游），所以"能出网"从未被证明过；而 §2.2 那条"放弃全学科、只做 arXiv 覆盖领域"的取舍、以及 R4 的整个应对方案，都建立在"可能出不了网、只能预置论文"这个假设上。

**实测结论：能出网。** 对已发布站点发一次 `GET ?action=fetch-paper&arxivId=1706.03762`，Function 成功抓取 `export.arxiv.org/html/1706.03762` 并解析：

| 指标 | 实测值 |
|---|---|
| 状态 / 耗时 | `200`，1.46–1.73 s |
| 解析结果 | 64 段正文、5 个公式、20 个章节标题，`truncated: false` |
| 第二篇交叉验证 | `2401.04088`（Mixtral of Experts）→ `200`，1.46 s，38 段、3 公式 |
| 回给读者的链接 | `https://arxiv.org/abs/1706.03762v7` — 带版本号，指向正文实际解析的那一版，不是 export 镜像 |

**假设一推翻，就有一串连带结论：**

1. **R4 的前提没了。** 原应对是"降级到 abs 页文本 + 预置论文手工挑选"，现在预置论文从"唯一能读的东西"降回它本该是的位置：一份**示范**，用来保证评委点开就有内容、零等待。真实风险从"能不能出网"收窄成"某一篇论文有没有 LaTeXML 网页版"——而这个失败是**逐篇的、可见的、有文案的**（`paper_no_html` → 「这篇论文存在，但 arXiv 没有为它生成可解析的网页版」），不是全局的。
2. **构建期语料兜底方案不需要了。** 但纯解析器（`functions/arxiv-parse.ts`，无 I/O、无依赖）的**双运行时设计保留**：同一份代码在 Deno 里跑生产，在 Node 26 下靠类型剥离直接跑 `dev/test-arxiv-parse.ts` / `dev/test-arxiv-fetch.ts`。本机没装 Deno，这条本地测试通道是唯一能在发布前验证解析逻辑的手段，不能拆。
3. **真实导入立刻抓出了一个手工数据的错误。** 线上解析出的章节列表里，`3.2 Attention` 和 `3.2.1 Scaled Dot-Product Attention` 是**两个不同的章节**；而手工维护的 `data/demo-paper.ts` 一直把缩放点积那几段标成 `3.2`。已按 arXiv 自己的标题改正。这件事本身就是导入路径存在意义的证明——预置数据是这个产品的信誉展品，而它错了一个章节号，没人发现。

**上限是量出来的，不是拍的。** 用 `dev/measure-units.ts` 统计 102 段真实正文（64 + 38）：中位数 356–410 字符，p90 610–694，最长 1171，**超过 1200 的一段都没有**。所以 `MAX_TRANSLATE_CHARS = 2400` 相对最坏观测值有约 2 倍余量。配套的决定是：超长输入**拒绝**（`400 selection_too_long`）而不是悄悄截断——被截短的输入会回来一份"自信但不完整"的译文，那比失败更坏。线上实测确认：3169 字符的构造输入返回 `400`，且**没有产生任何部分答案**。

**顺手补上了一个一直存在的验证缺口。** `functions/` 被主 `tsconfig.json` 排除（服务端代码绝不能进浏览器包），本机又没有 Deno，所以 `npm run check:function` 一直是坏的——**Function 代码从来没被类型检查过**，类型错误只会在边缘运行时抛出来，在生产环境，在评委面前。新增 `tsconfig.functions.json` + `dev/deno.d.ts`（只声明实际用到的 `Deno.env.get` 与 `Deno.serve`，故意不做通用 Deno shim：将来 Function 要用新能力，必须先在这里声明，这个摩擦是设计出来的），并挂进 `npm run build`。**它立刻抓出一个真实错误**：`functions/explain.ts` 里 translate 分支的三元表达式让字面量被推断成 `{ ok: boolean }`，判别式丢失，`question.code` 不再可访问。已修。

**网关的 CSRF 防线从推断升级为实测。** §6.5.2 第 3 条原话是"网关自己挡住了跨源 POST，这层不是我写的"——当时是推断。现在量到了：不带 `Origin` 的 POST → `403 sites_gateway_origin_forbidden`；`PUT` 不带 Origin → `403`（网关层），带同源 Origin → `405`（Function 自己的 `method_not_allowed`）。**两层都拒**，处理器的 405 是纵深防御而不是唯一防线。这也意味着任何命令行验证都必须显式带 `Origin`，否则会误判成后端故障。

**浏览器内真实交互验证（不是 curl）。** 线上站点，走评委的路径：

- 预置论文：9 段全部渲染，9 条中文对照、9 个作用标签齐全，公式卡片标题是「人话拆解」。

## 附四：把"扉页家具"当成一类问题来解（11/16）

附三留下的 R13 不是"断段规则写得不够多"，而是"只在 3 篇 CS 论文上测过"。这一轮的做法因此是**先补样本、再补规则**：收四篇不同学科的 arXiv PDF（数学 2012.12675 / 经济 2012.11542 / LNCS 会议版 2012.13779 / IEEE 地球科学 2012.11922），先让它们在测试里失败，再把每条规则的注释写成"是被哪篇论文的哪个数字逼出来的"。这四篇现在是 `dev/test-pdf-layout.ts` 的**常驻夹具**（`dev/probe-stages.ts` 留作逐阶段诊断工具，不是测试、不进构建）。

**六条规则，六条测出来的数**：

1. **脚注的行距参照正文，不参照本页**。2012.11542 第 1 页的中位行距是 24.9 pt，正文只有 12 pt；拿"1.8 倍本页行距"当门槛，这个封面页的空隙任何脚注都超不过，反之别的页的脚注全被放过。于是把参照量截到 1.4 倍正文字号——这个上界只可能让规则看见更多脚注，不可能看见更少。
2. **有标记的页面底部行，即使上面没留空也是脚注**。2012.11922 那句 "? Paper published in … Lecture Notes in Computer Science, vol 9785. Springer, Cham." 距上一行 23 pt，在 12 pt 文档里只有 1.3 倍行距，卡在旧门槛下面，于是它成了读者的第 3 段"正文"。加 `MARKER_OPEN`（星号/ dagger/ 数字/ 引号起头）作为与"留空够大"并列的条件。
3. **小括号里的状态说明不是正文**："(Preliminary version)" 这种整行 → `STATUS_PARENTHETICAL`，走扉页采集的同一道判据。
4. **以国家名收尾的一行不是人名**：BIST 那行把 Institute 拼成了 "Institue"，`institut\w*` 匹配不上，而 "of" / "and" 在 `looksLikeNames` 里算名字小品词，于是 "…Barcelona, Spain" 整行被当成第三作者收下。国家名不可能是人名的一部分 → `ENDS_WITH_COUNTRY`。
5. **关键词表、学科分类码、DOI 链接是索引卡，不是能逐句读的文字** → `METADATA_LABEL` + `isLinkList`（两条以上裸 URL 且剩下的散文不足 40 字符）。四篇模板里最常见的泄漏就是 Keywords 块，所以这条按"标签"而不是按"位置"来判。**摘要刻意留在正文里**——它是可以划词提问的。
6. **联系信息按内容剔除，不按大小写剔除**：`\bhttps?:\b` 匹配不到 `http://isp.uv.es/`（冒号两边都没有词字符），这行被当成最后一位作者的第二个名字收进了作者串。`EMAILISH` 改成直接看 `https?:/{2}`，并在跨行续接那条分支上再加一道 `!EMAILISH`——续接行常常是小写开头，正好是散文的形状。

另外：LNCS 的作者名把重音排成独立字符（"Adri´ an"），`SPACING_ACCENTS` 把它拼回组合字符，读出来才是 "Adrián F. Amil"；同一处还顺手修掉 ` ,`、`and,` 和游离的上标标记。

**删除不再是无声的**（这一步同时收窄了 R14）：`omittedFootnotes` 与 `omittedMetadata` 各自生成一条 `parseNotes`——"页面底部的 N 行脚注没有读入……需要看它请回原 PDF""扉页的 N 段标签（关键词表、学科分类码、DOI 链接）没有读入……摘要保留了"。读者看见的是计数和去处，不是一个查不到的空洞。
